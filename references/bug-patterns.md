# 缺陷模式

## 多步骤 Git 操作必须共享同一把锁

- 适用场景：安全备份后删除、分支保护后重置、连续配置更新、批量 Cherry-pick、交互式 Rebase。
- 风险：每条命令单独加锁仍允许其他写操作插入步骤之间，导致检查结果过期或仓库进入不一致状态。
- 处理：以 Git 公共目录作为锁键，在整个检查、保护和修改流程外层持锁；内部命令使用不重复加锁的受跟踪执行器。

## 破坏性操作必须保存“缺失状态”

- 适用场景：Patch 新增文件、恢复备份、清理和丢弃文件。
- 风险：只复制现有文件无法表达“操作前文件不存在”，恢复时会遗留新增文件。
- 处理：备份清单分别记录已有路径和原本缺失路径；恢复时先备份当前状态，再清理目标并还原快照。

## Git 输出必须在所有出口脱敏

- 适用场景：命令日志、成功响应、stderr/stdout 错误响应。
- 风险：只清理日志仍可能通过接口错误信息泄露 URL 用户名、密码或令牌。
- 处理：原始输出保留用于判定，所有展示出口统一执行 URL 凭据替换。
