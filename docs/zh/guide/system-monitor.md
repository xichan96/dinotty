# 系统监控

Dinotty 内建系统监控面板，实时显示服务端的 CPU、内存、网络指标。无需另装 htop / Activity Monitor。

## 打开监控

| 方式 | 操作 |
|------|------|
| 终端工具栏 | 点击 pane 标题栏右侧的「监控」图标 |
| Command Palette | 输入 `monitor.open` |
| 设置 -> 监控 | 查看长时间历史数据 |

监控数据来自服务端，反映的是**服务端主机的负载**，不是客户端的负载。

## 实时指标

| 指标 | 说明 |
|------|------|
| CPU | 总体占用百分比 + 每核心折线图 |
| 内存 | 已用 / 总量 / 交换分区使用 |
| 网络 | 入站 / 出站流量（KB/s） |
| 进程数 | 服务端进程总数 |

默认每 1 秒刷新一次。可在设置里调整刷新间隔（1s / 2s / 5s）。

## 历史数据

监控面板下方显示过去 60 秒的折线图：

- CPU 折线（红）
- 内存折线（绿）
- 网络流量折线（蓝）

鼠标悬停查看具体数值。历史数据保存在内存中，重启服务后清空。

## 监控弹层

终端 pane 顶部的 MonitorPopover 是轻量弹层：

- 点击「监控」图标弹出
- 不切换 pane，叠加在当前 pane 上方
- 显示当前 pane 占用情况（PTY 输出量、子进程 CPU / 内存）

适合排查某个 agent 是否卡死 / 占用过高。

## 典型用法

### 排查 agent 卡死

agent 跑着跑着没响应：

1. 打开该 pane 的 MonitorPopover
2. 看 PTY 输出量是否还在增长
3. 看子进程 CPU 是否归零（agent 已退出 / 等待输入）
4. 看子进程内存是否爆涨（OOM 前兆）

### 服务器负载监控

部署在 VPS 上的服务端：

1. 远程打开 Dinotty
2. 设置 -> 监控 看长时间历史
3. 发现 CPU 持续 90%+，定位异常进程

### 多端共享监控

服务端只有一份监控数据，所有连接的端看到同样的视图。手机上也能看服务端负载。

## 通知集成

可在设置里配置阈值通知：

- CPU 超过 80% 持续 30 秒 -> 触发通知
- 内存使用超过 90% -> 触发通知

通知通过 [通知系统](../features/notifications) 推送到所有端。
